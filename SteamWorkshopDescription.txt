[h1]RSS Orbital Navigator[/h1]

A server-side navigation display for Space Engineers worlds using [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3351055036]Real Solar Systems[/url]. Current release: 0.9.0.

The current release supports the [url=https://steamcommunity.com/sharedfiles/filedetails/?id=3367704014]Trithorne Cluster[/url] preset world. It reconstructs logical orbital positions and displays route distance, Jump Drive range, closest approach, and estimated jump windows on LCD surfaces.

[h2]Features[/h2]

[list]
[*]Responsive dashboard for LCDs, cockpits, and console surfaces
[*]Logical RSS orbital distance calculations
[*]Automatic Jump Drive range and charge detection
[*]Estimated departure and arrival allowances
[*]Jump-window opening and closing predictions
[*]Approaching, open, closing, and error status colors
[*]Optional Sound Block alert when a usable window opens
[*]Dashboard and detailed text display modes with Button Panel route selection
[*]RSS logical ship-position integration for deep-space checks
[*]Short-horizon ship trajectory estimates after position sampling
[*]Current ship-to-planet Jump Drive reachability checks
[*]Dedicated-server and Torch-compatible
[/list]

[h2]Requirements And Supported Worlds[/h2]

This mod requires:

[list]
[*][url=https://steamcommunity.com/sharedfiles/filedetails/?id=3351055036]Real Solar Systems[/url]
[*][url=https://steamcommunity.com/sharedfiles/filedetails/?id=3367704014]Trithorne Cluster preset world[/url]
[/list]

RSS Orbital Navigator currently contains the orbital catalog and timing model for the Trithorne Cluster. Other Real Solar Systems configurations are not yet supported.

Real Solar Systems also requires its own dependencies. Subscribe to the required items listed on its Workshop page.

[h2]Quick Setup[/h2]

1. Add this mod to the world.
2. Rename an LCD, cockpit, or console block so its name contains:

[code][RSSNAV][/code]

3. Add the following to the block's Custom Data:

[code]
[RSSNAV]
SourceBody=Luburn
TargetBody=Tropol
Surface=0
DisplayMode=Dashboard
FontSize=0.55
PredictionHours=48
ShipForecastMinutes=30
PanelUpdateRadiusKm=0.2
ModelEpoch=2081-01-01T00:00:00
TimeOffsetSeconds=0

JumpRangeMode=Auto
JumpIdentityId=0

NavigationMode=Auto
SourceRadiusMode=Auto
SourceDepartureRadiusKm=0
TargetArrivalMode=OrbitZone
TargetArrivalRadiusKm=0
TargetSafetyMarginKm=25

ColorAlertsEnabled=true
AlertLeadMinutes=30

SoundAlertEnabled=false
SoundBlockTag=[RSSNAV ALERT]
SoundCooldownSeconds=300
SoundOnStartup=false
SoundRequireApiValid=true

ShowDiagnostics=false
Title=RSS ORBITAL NAVIGATOR
[/code]

For smaller cockpit displays, try:

[code]FontSize=0.40[/code]

For blocks with multiple displays, change [code]Surface=0[/code] until the dashboard appears on the desired surface.

[h2]Planetary And Deep-Space Navigation[/h2]

Navigation mode defaults to automatic:

[code]NavigationMode=Auto[/code]

In Auto mode, the mod uses the source planet voxel when the ship is near the configured source body. When no plausible source voxel is nearby, it automatically switches to deep-space behavior, uses zero source departure allowance, and labels the display [code]AUTO DEEP SPACE[/code].

When the RSS logical-position API is available, deep-space mode converts the ship position into RSS proxy space and performs a current ship-to-target range check. After two samples, it estimates relative required-distance movement for the configured [code]ShipForecastMinutes[/code] horizon. If the API or target body is unavailable, it shows an amber [code]POSITION UNKNOWN[/code] state, labels body-to-body values as reference only, and suppresses unverified predictions and sound alerts.

In RSS-position deep-space mode, the route header shows [code]SHIP > Target[/code]. [code]SourceBody[/code] remains configuration context but is not treated as the ship's physical departure point.

[h2]Display Modes[/h2]

[b]Dashboard[/b] displays a responsive sprite-based navigation console with route, range, jump-window, motion, forecast, and Jump Drive information.

[b]Text[/b] displays the detailed legacy report and is useful for diagnostics or very small surfaces.

Set the mode in Custom Data:

[code]DisplayMode=Dashboard[/code]

or:

[code]DisplayMode=Text[/code]

The dashboard reports route, estimated jump, available range, jump-window status, motion, forecast, and Jump Drive information. Status colors are white for monitoring, yellow for opening soon, green for open, orange for closing, and red for errors.

[h2]Sound Alerts[/h2]

1. Add a Sound Block to the same construct as the LCD.
2. Include this tag in its name:

[code][RSSNAV ALERT][/code]

3. Select a short, non-looping sound.
4. Enable sound alerts in Custom Data:

[code]
SoundAlertEnabled=true
SoundBlockTag=[RSSNAV ALERT]
[/code]

The sound plays once when the system transitions into a usable jump window. Cooldown protection prevents repeated playback during subsequent updates.

[h2]Important Notes[/h2]

The mod uses RSS logical coordinates rather than physical planet or GPS positions. Jump geometry assumes favorable radial alignment; obstacles, gravity restrictions, and the final RSS transition must still be checked manually. Static grids report zero usable range, and Nyph-Ea remains approximate.

[h2]Performance[/h2]

The navigator limits its server-side simulation cost:

[list]
[*]Displays are evaluated approximately every five seconds, not every simulation tick.
[*]Calculations, alerts, and rendering run only when a player is within [code]PanelUpdateRadiusKm[/code].
[*]The default proximity radius is [code]0.2 km[/code] (200 m), matching the distance at which a player is normally close enough to use the display.
[*]When no players are connected, the mod skips the global entity scans entirely.
[*]When no tagged panels are found, discovery backs off to occasional retries.
[*]A panel outside the proximity radius retains its last displayed content until a player comes close again.
[/list]

Increase [code]PanelUpdateRadiusKm[/code] if remote players need to see a panel from farther away. Larger values increase the number of panels that may perform orbital calculations during each update.

[h2]Troubleshooting[/h2]

Check the Space Engineers or Torch log for:

[code][RSS Orbital Navigator][/code]

If a display remains blank, verify:

[list]
[*]The block name contains [code][RSSNAV][/code]
[*]The configured surface index is valid
[*]The source and target body names are valid
[*]The mod is enabled in the world
[*]The server loaded the mod without compilation errors
[*]Real Solar Systems and its dependencies are installed
[/list]
